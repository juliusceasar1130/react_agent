# Spec: 主子智能体 AskUserQuestion 持久化、历史无损回放与已确认胶囊摘要折叠（第三阶段）

Triage Label: `ready-for-agent`

## Problem Statement

在完成了状态语义解耦（第一阶段）和角色归属与交互联动（第二阶段）后，澄清问答的人机交互（HITL）体验已显著提升。然而在跨会话与多轮长对话场景下，仍存在以下数据持久化与历史呈现方面的**结构性断层**：

1. **历史回放数据丢失（刷新即消失）**：
   - 目前数据库消息实体中缺少结构化的 `questions`（问题列表）与 `clarification_answers`（用户答复）独立字段。当用户刷新页面或在左侧会话列表中切换历史会话时，大模型在生成过程中发起的澄清提问与用户的选择记录完全丢失，无法在聊天流中复现当时的决策依据。
2. **已确认卡片占用垂直篇幅过大**：
   - 在当前会话内存中，用户提交答复后，卡片虽然转为禁用只读态，但依然展开了所有单选/多选项与多行文本框，占据了大量屏幕垂直高度。随着多轮对话进行，冗长的只读表单割裂了上下文，严重干扰用户的长文阅读。
3. **缺乏结构化答复摘要**：
   - 用户无法一目了然地回顾“我刚刚补充了哪些参数”，只能在长文本或工具结果中费力推断。

---

## Solution

在后端实现**澄清问答结构化持久化**，在前端实现**已确认胶囊摘要折叠与无损历史回放**：

1. **数据库与数据模型无损扩展（Persistence）**：
   - 在数据库消息表中引入结构化列支持，保存 `questions` 与 `clarification_answers`（采用幂等升级与向后兼容设计）；
   - 在中断恢复（`/resume`）和最终消息落库时，将用户答复与对应的问题包完整持久化；
   - 会话历史查询接口（`/api/chat/messages`）完整透传澄清数据。
2. **已确认胶囊摘要折叠组件（Capsule Summary Folding）**：
   - 当卡片处于已提交态（`isSubmitted: true`）或历史回放态时，默认收拢为一行精致的胶囊摘要条：
     > ✅ **已确认补充信息**：`读写站: Station A` ｜ `车身号: 7820261103` ｜ 展开详情 ▾
   - 胶囊条直观提炼出每个问题的标题与用户最终选定/填写的核心值。
3. **展开/收起平滑微交互**：
   - 胶囊条右侧提供“展开详情 / 收起”切换按钮，点击后平滑展开当时的完整只读表单（标记用户的勾选与自定义输入），支持随时折叠回摘要态。

---

## User Stories

1. As a 业务分析人员, I want 在多轮对话中，已回答完的澄清表单自动收拢为一行简洁的摘要胶囊, so that 聊天界面保持清爽整洁，不干扰我阅读核心分析报告。
2. As a 业务分析人员, I want 在摘要胶囊上一眼看到我当时选择的关键参数（如站点名称、车身号）, so that 我能清晰确认大模型是基于何种参数口径进行的后续计算。
3. As a 业务分析人员, I want 点击摘要胶囊右侧的“展开详情”随时查阅当时的完整备选项与历史表单, so that 我能复盘当时大模型提供了哪些选择分支。
4. As a 业务分析人员, I want 刷新页面或切换历史会话后，当时所有的澄清问答和我的答复依然完整回放展示, so that 历史会话具备完整可追溯的上下文事实。
5. As a 开发者, I want 数据库迁移脚本具备幂等安全性（`ADD COLUMN IF NOT EXISTS`），不影响现有存量历史消息数据, so that 系统在升级过程中具备零故障热迁移能力。
6. As a 开发者, I want 历史消息回放逻辑对缺失澄清字段的旧数据具备安全降级回退, so that 系统具备 100% 向后兼容性。

---

## Implementation Decisions

1. **数据持久化与数据库表结构**
   - 在数据库消息表中扩展 `questions`（JSON/Text）与 `clarification_answers`（JSON/Text）列；
   - 在应用启动的表结构初始化逻辑中加入幂等字段检查与安全自动迁移；
   - 在后端 `MessageSchema`、`MessageCreate` 及 ORM 模型中建立映射。
2. **`/api/chat/resume` 答复持久化闭环**
   - 用户提交回答调用 `/resume` 路由时，系统将提交的 `answers` 数据持久化到该轮澄清消息实体中，确保问答对应关系不丢失。
3. **前端 Store 历史回放映射**
   - `messagesStore` 在调用 `fetchMessages` 载入历史记录时，将持久化的 `questions` 与 `clarification_answers` 还原至前端状态模型；
   - 历史消息中的 `AskUserQuestionCard` 自动识别为已完成态。
4. **`AskUserQuestionCard.vue` 胶囊折叠与摘要生成**
   - 内部抽象出 `formattedSummary` 计算属性：提取每个问题的提问关键词与选中的 `answer` 字符串，拼接为易读的一行标签；
   - 当 `isSubmitted === true` 时，默认展示 `<div class="capsule-summary">`，并由本地响应式变量 `isExpanded` 控制完整表单的折叠与展开。

## Testing Decisions

### 良好测试的标准
- 验证新会话中提交答复后数据库中正确落库 `questions` 与 `clarification_answers`；
- 验证历史消息接口重新读取时能够正确反序列化并返回澄清问答数据；
- 验证前端在已提交和历史回放态下默认展示胶囊摘要，点击“展开详情”后能够无损切换展示完整表单。

### 重点测试范围
- `models.py` & `crud.py`：测试包含澄清字段的消息 CRUD 与迁移幂等性；
- `routers/chat.py`：测试 `/resume` 路由保存答复并在历史列表中正确输出；
- `AskUserQuestionCard.vue`：测试胶囊摘要文本计算、展开/收起状态切换与只读锁定。

---

## Out of Scope

1. **历史已提交表单的二次编辑与回滚重算**（保持会话历史的只读不可变事实链）。
2. **多租户审计日志导出**（仅聚焦会话界面内的持久化与呈现）。

---

## Further Notes

- 数据库扩展仅新增两个向后兼容的可空字段，迁移成本极低。
- 胶囊折叠态将大幅净化界面，使长会话阅读体验达到现代化大模型应用的顶级标准。
