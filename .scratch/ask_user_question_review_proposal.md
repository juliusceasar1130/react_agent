# 提案：主智能体与子智能体 AskUserQuestion 交互体验与前端展示优化评审

## 一、背景与现状

在当前系统中，主智能体与子智能体（如 `sql_domain_agent`）均配备了 `AskUserQuestion` 澄清工具。当执行过程中遇到需求模糊、缺少关键过滤参数（如车身号 FIS、读写站）或技术权衡时，系统通过 LangGraph 原生 `interrupt({"type": "ask_user_question", "questions": [...]})` 挂起执行图，并向前端推送 `type: "interrupt"` SSE 事件。

### 前端当前显示机制：
1. **统一挂载**：无论由主智能体还是子智能体发起，前端均在最外层消息底部（`MessageItem.vue`）挂载 `AskUserQuestionCard.vue`。
2. **交互形式**：支持单选/多选/纯文本输入/混合参数输入，并在提交后调用 `/api/chat/resume` 恢复执行，随后锁定历史卡片为 disabled 状态。
3. **子智能体卡片状态**：`SubagentCard.vue` 内部展示子智能体的推理与工具调用链。当子智能体调用 `AskUserQuestion` 挂起时，其标签状态变为 `interrupted`（显示黄色警示“已中断”）。

---

## 二、当前存在的体验问题

1. **状态文案歧义（误导性恐慌）**：
   - 触发挂起时，外层消息顶部显示“已停止生成”，子智能体标签显示“已中断（⚠️黄色感叹号）”。
   - 用户极易误以为系统发生崩溃、出错或任务被强制终止，而非正常的“等待用户确认/补充信息”。
2. **提问角色来源缺失**：
   - `AskUserQuestionCard` 头部仅有 `问题 1/2` 和 `item.header`（如“参数确认”），未标明是由“通用主助手”还是“SQL数据专家”发起的提问，多智能体协同下用户缺少上下文归属感。
3. **视线聚焦与联动断层**：
   - 当子智能体卡片展开较长时，用户视线留在日志区，不知道需要滚动到底部填写表单；缺乏卡片与子智能体之间的视觉指示和锚点联动。
4. **历史卡片冗余**：
   - 已完成并提交的历史卡片依然完整展开所有选项和输入框，随着多轮对话进行，占据过多垂直屏幕空间。
5. **快捷键与操作效率**：
   - 缺少 `Ctrl+Enter` 快速提交及单选双击快速确认等键盘友好操作。

---

## 三、拟定的 5 项优化方案

1. **方案 1：状态文案与语义解耦（高优先级）**
   - 当 `isInterrupted` 伴随 `questions`（等待澄清）时：
     - 外层消息顶部显示：“⏳ 等待您的确认” / “💬 需要补充信息”（配合蓝色/紫灰色呼吸微光），而非“已停止生成”。
     - 子智能体卡片状态标签由“已中断”改为“等待确认”（配合温和状态标签）。
   - 仅在用户主动点击“取消”或“停止”时，才显示“已停止生成/已取消”。
2. **方案 2：卡片增加智能体角色标识**
   - 在 `AskUserQuestionCard` 头部增加智能体身份来源徽章（如【🤖 SQL数据专家 发起澄清】或【来自数据分析助手的提问】）。
3. **方案 3：子智能体卡片与提问卡片联动**
   - 在 `SubagentCard` 的工具链末尾，若停在 `AskUserQuestion`，显示提示条：“正在等待您在下方卡片中确认参数”，并支持点击平滑滚动锚定到底部表单。
4. **方案 4：历史已提交卡片的紧凑折叠与摘要胶囊**
   - 历史消息中的已提交卡片默认收拢为紧凑的胶囊摘要（如：`✅ 已确认: 读写站: Station A | FIS: 7820261103`），支持点击展开查看当时的完整表单。
5. **方案 5：快捷键与键盘交互增强**
   - 支持 `Ctrl+Enter` / `Cmd+Enter` 快速提交表单，支持选项键盘导航。
