# 前后端与 Nginx 架构知识总结

本文件总结了项目中前端、后端以及 Nginx 之间的协作关系与核心配置逻辑。

---

## 1. 核心组件定义

### **前端 (Frontend)**
*   **本质**：静态文件（HTML, JavaScript, CSS, 图片等）。
*   **职责**：用户交互界面、数据展示、发起 API 请求。
*   **在本项目中**：Vue/Vite 项目，通过 `baseURL: '/rearch'` 发起相对路径请求。

### **后端 (Backend)**
*   **本质**：运行中的程序逻辑（FastAPI / Python）。
*   **职责**：处理业务逻辑、操作数据库、提供数据接口。
*   **在本项目中**：运行在 Docker 容器内的 8000 端口，通过端口映射暴露给宿主机。

### **Nginx (Web服务器/反向代理)**
*   **职责**：流量的总入口（门卫/传菜生）。
*   **核心功能**：
    1.  **分发流量**：区分静态资源和动态 API。
    2.  **反向代理**：将外部请求转发给后台真实的端口（如 8000）。
    3.  **解决跨域 (CORS)**：让前后端在同一个域名/端口下，规避浏览器限制。

---

## 2. 请求流向 (Request Lifecycle)

当你访问 `http://172.22.44.99/rearch` 时，发生了什么？

1.  **初次加载**：
    *   浏览器请求 `172.22.44.99/rearch`。
    *   **Nginx** 拦截请求，去磁盘找到前端 HTML 文件并返回。
    *   浏览器解析 HTML，显示网页。

2.  **接口交互**（如点击“发送”消息）：
    *   浏览器发起请求：`POST /rearch/api/chat`。
    *   **Nginx** 识别到 `/rearch` 或 `/api` 路径。
    *   **Nginx 转发**：根据配置，将请求转发到宿主机的 `http://127.0.0.1:8000`。
    *   **进入 Docker**：流量通过容器的 8000 映射端口，到达 Python 程序。
    *   **原路返回**：Python -> Docker 映射 -> Nginx -> 浏览器。

---

## 3. 关键配置项说明

### **前端配置 (src/api/index.ts)**
```typescript
baseURL: '/rearch' // 不写死端口，由 Nginx 统一转发
```

### **Docker 配置 (docker-compose.yml)**
```yaml
ports:
  - "8000:8000" # 将容器内的 8000 映射到宿主机的 8000
```

### **Nginx 配置 (典型代码段)**
```nginx
location /rearch/api/ {
    proxy_pass http://127.0.0.1:8000/; # 将匹配到的请求推往后端
    proxy_set_header Host $host;       # 保持原始请求头信息
}
```

---

## 4. 为什么使用 Nginx？

1.  **安全性**：后端 8000 端口可以不对公网开放，只允许 Nginx 访问。
2.  **性能**：Nginx 处理图片、JS 等静态资源的速度极快，减轻后端压力。
3.  **高可用**：如果未来有多个后端实例，Nginx 可以实现负载均衡（随机分单）。
4.  **标准化**：统一了入口（通常是 80 或 443 端口），用户无需记住复杂的端口号。
