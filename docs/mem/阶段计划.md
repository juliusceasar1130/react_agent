# 用户反馈驱动型 SQL 案例自演进系统实施计划

本项目拟实现一个基于用户反馈（Thumbs up/down/Star 收藏）、异步大模型（LLM）意图提炼和 **Milvus 向量库** 存储的 Few-Shot SQL 动态案例库。通过该系统，智能体能在运行中自我吸收黄金案例，并在相似提问中动态参考，从而彻底解决复杂 SQL 生成幻觉和长尾口语/方言识别难的问题。

---

## 1. 优先级开发阶段细分

### 阶段一：反馈收集基础建设与落库 (Priority: High 🔴 | 已完成 ✅)
**目标**：打通用户点击“赞/踩/收藏”到数据库存储的完整链路，这是所有后续提炼的数据源头。
*   **Step 1: 数据库模型修改**：在 `models.py` 中为 `ChatMessage` 模型添加 `feedback` 列。
*   **Step 2: 编写数据库迁移及 Schema**：在 `schemas.py` 中增加 `MessageFeedbackRequest` 模型。
*   **Step 3: CRUD 与 API 路由开发**：在 `crud.py` 中新增 `update_message_feedback()`，并在 `api.py` 中开发 `POST /api/chat/messages/{id}/feedback` 保存用户反馈。
*   **Step 4: 前端 UI 操作面板**：在 `MessageItem.vue` 中为 AI 消息卡片底部，添加赞、踩、收藏操作按钮并对接状态。

### 阶段二：规则提取器管道与拓扑精准回溯 (Priority: High 🔴 | 已完成 ✅)
**目标**：开发 `RuleExtractor` 过滤体系，在不消耗 LLM 的情况下快速过滤劣质 SQL，并依据 `tool_call_id` 高效回溯上下文。
*   **Step 1: 构建规则提取管道基础类**：创建 `rule_extractor.py`，实现 `ExtractionContext`、`BaseFilter` 和 `PipelineManager`。
*   **Step 2: 实现三大静态校验过滤器**：
    *   `SafetyWarningFilter`：拦截含安全警告或含有 `DROP`/`DELETE`/`TRUNCATE` 敏感词的 SQL。
    *   `SingleSqlFilter`：忽略执行失败的 SQL；若单回合执行了多次不同 SQL（多步查询），直接触发极简舍弃策略。
    *   `EmptyResultFilter`：检查 SQL 返回结果，若为空则拦截。
*   **Step 3: 实现基于 `tool_call_id` 的拓扑精准回溯器**：编写 `TopologyBacktrackFilter`，依据 tool call ID 向上反查多轮澄清会话。
*   **Step 4: 实现业务域提取**：编写 `DomainFilter` 提取 Skill 元数据。

### 阶段三：管理员审批、LLM 意图提炼与 Milvus 写入 (Priority: Medium 🟡 | 已完成 ✅)
**目标**：采用 Flow B 优化方案（预提纯，同步入库），将 LLM 重写与脱敏前置到收藏动作触发时，使管理员审核直接查看预备好的草稿，并 0 延迟即时落库。
*   **Step 1: 扩展模型草稿字段**：`ChatMessage` 模型新增 `refined_payload` 字段，存储 LLM 预提纯好的草稿。
*   **Step 2: 触发前置异步处理**：在用户点击收藏（Collected）时，立即在后台拉起 `process_collected_message_async` 异步任务，进行规则过滤和 LLM 提炼（指代消解意图重写与 SQL 脱敏），并将草稿保存到 `refined_payload`；如果规则初筛未通过，自动重置 `feedback = 'none'` 踢出审核队列。
*   **Step 3: 编写审批与落库逻辑**：在 api.py 中发布 `POST /api/chat/admin/messages/{id}/approve`。批准后，从 `refined_payload` 提取数据或从管理员微调参数中获取，同步调用 `add_document_to_store` 将黄金案例写入 Milvus 向量库，随后状态更新为 `'approved'`。

### 阶段四：管理端审核终端与接口配套 (Priority: Medium 🟡 | 已完成 ✅)
**目标**：开发可视化的管理员审核终端界面，方便管理员在线审查预提纯草稿并一键批准入库。
*   **Step 1: 编写待审核案例拉取接口**：在 `api.py` 新增 `GET /api/chat/admin/messages/pending` 接口，拉取所有带草稿的 `collected` 状态案例。
*   **Step 2: 设计审核终端前端 UI**：新建 `AdminReviewPanel.vue` 组件，在 `ChatView.vue` 顶部 Header 新增切换按钮，管理员可一键进入审核终端，直观微调提炼草稿并调用批准。

### 阶段五：大模型自主案例检索工具优化 (Priority: Low 🟢 | 未开始 ⏳)
**目标**：优化 Agent 已持有的 `search_saved_correct_tool_uses` 工具，让大模型在编写 SQL 前通过该工具自主检索相似黄金案例，实现业务域（Domain）之间的硬性强隔离。
*   **Step 1: 优化自主案例检索工具的隔离性**：修改 `sql_tools.py` 中的 `search_saved_correct_tool_uses` 工具定义，将大模型调用时填入的 `required_skill` 核心参数透传给底层检索器（`retriever.retrieve(..., domain=required_skill)`）。
