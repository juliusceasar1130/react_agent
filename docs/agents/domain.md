# Domain Docs

工程技能在探索代码库时应如何消费本仓库的领域文档。

本项目遵循 **单上下文 (Single-context)** 布局来管理领域知识。

## 探索前必读

- **`CONTEXT.md`** — 仓库根目录下的全局上下文文件，包含业务术语。
- **`docs/adr/`** — 架构决策记录（若存在），在修改相关区域前需阅读。

如果这些文件不存在，**静默处理**。不要标记缺失，也不要建议立即创建。

## 文件结构

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

## 使用规则

1. **优先阅读**: `improve-codebase-architecture`、`diagnose` 和 `tdd` 等技能必须先阅读 `CONTEXT.md` 以理解业务术语。
2. **参考 ADR**: 在进行结构性改动前，检查 `docs/adr/` 以确保与过去的决策保持一致。
3. **使用术语表的词汇**: 当输出中命名领域概念时，使用 `CONTEXT.md` 中定义的术语。
4. **标记 ADR 冲突**: 如果输出与现有 ADR 矛盾，明确指出来而非静默覆盖。
5. **同步更新**: 当产生新的业务术语或架构决策时，及时更新这些文档。
