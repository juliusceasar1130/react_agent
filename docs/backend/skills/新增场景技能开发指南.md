# 新增场景技能开发指南

修改时间：2026-04-06 21:22 Asia/Shanghai

主要修改内容：
- 更新为“按场景目录聚合 + 自动发现”新增流程
- 补充 `scope + path` 资产引用写法
- 明确 `shared/` 公共资产与场景私有资产的边界

## 背景

当前业务技能系统中，一个固定场景应当被维护成一个完整目录，而不是把 `.py`、`.sql`、脚本分散在多个并列目录中。

推荐使用场景 skill 的典型情况：

- 高频重复出现
- 统计口径稳定
- workflow 固定
- 输出结构比较稳定
- 后续有可能升级为模板执行器或专用 tool

## 目标目录结构

以 `current_area_distribution` 为例：

```text
backend/app/skills/domains/paint_shop_vehicle_logistics/
  scenarios/
    current_area_distribution/
      scenario.py
      sql/
        main.sql
      scripts/
```

如果多个场景共享资产，再放到：

```text
backend/app/skills/domains/paint_shop_vehicle_logistics/shared/
  sql/
  scripts/
```

## 新增场景的标准步骤

### 第 1 步：创建场景目录

示例：

```text
backend/app/skills/domains/paint_shop_vehicle_logistics/scenarios/current_area_distribution/
```

建议至少创建：

```text
current_area_distribution/
  scenario.py
  sql/
    main.sql
```

### 第 2 步：编写 `scenario.py`

参考模板：

```python
SCENARIO = {
    "skill_name": "paint_shop_vehicle_logistics",
    "name": "current_area_distribution",
    "title": "当前各区域车身分布",
    "description": "统计当前快照下各工艺区域的有效车身数量分布。",
    "triggers": [
        "当前各区域有多少车",
        "查看区域车身分布",
        "统计当前区域车辆情况",
    ],
    "intent_keywords": ["区域", "分布", "当前", "车身数量"],
    "required_inputs": [],
    "optional_inputs": ["process_area"],
    "parameters": {
        "process_area": {
            "type": "array",
            "items_type": "string",
            "description": "工艺区域名称列表，用于筛选特定区域的车身数量",
            "required": False,
            "source_column": "process_area",
            "source_table": "process_areas",
            "example_values": ["电泳", "面漆", "烘干"],
            "usage": "当用户询问特定区域时，将此参数添加到 SQL 的 WHERE 子句中",
            "sql_fragment": "AND rp.process_area IN ('{values}')",
        }
    },
    "workflow": [
        "确认是否为当前快照统计。",
        "应用有效车辆规则。",
        "按 process_area 聚合统计。",
        "输出区域分布和总计。",
    ],
    "rules": [
        "只统计有效车辆。",
        "聚合必须在数据库中完成。",
    ],
    "gotchas": [
        "当前快照与时间窗口不能混用。",
    ],
    "output_contract": "输出 process_area、vehicle_count，并附带口径说明。",
    "sql_template_refs": [
        {
            "type": "sql",
            "name": "main",
            "scope": "scenario",
            "path": "sql/main.sql",
            "description": "当前区域车身分布 SQL 模板。",
        }
    ],
    "script_refs": [],
}
```

关键约束：

- 目录名必须等于 `SCENARIO["name"]`
- `SCENARIO["skill_name"]` 必须等于所属领域名
- 不要把大段 SQL 正文写进 `scenario.py`

### 第 3 步：编写 `sql/main.sql`

示例：

```sql
SELECT
    rp.process_area,
    COUNT(*) AS vehicle_count
FROM rb_position_data rp
WHERE rp.vehicle_id LIKE '782026%'
  AND rp.body_type != '-----'
  AND rp.carrier_id <> '0'
GROUP BY rp.process_area
ORDER BY vehicle_count DESC;
```

建议：

- 主查询统一放在 `sql/main.sql`
- 如果场景有多个 SQL，可继续在 `sql/` 下扩展
- 若多个场景共享同一 SQL 片段，再抽到领域级 `shared/sql/`

### 第 4 步：按需引用共享资产

若要引用领域共享资产，使用：

```python
{
    "type": "doc",
    "name": "shared_scripts_readme",
    "scope": "shared",
    "path": "scripts/README.md",
    "description": "共享脚本目录说明",
}
```

`scope` 约定：

- `scenario`
  相对当前场景目录
- `shared`
  相对当前领域 `shared/`
- `domain`
  相对当前领域根目录

### 第 5 步：验证自动发现

新增场景后不再修改 `registry.py`，而是直接验证：

1. `list_scenarios_by_skill("<skill>")` 能返回新场景
2. `get_scenario_by_name("<skill>", "<scenario>")` 能查到
3. `load_scenario_content("<skill>", "<scenario>")` 能输出完整 playbook

## 参数定义建议

当场景支持动态筛选时，`parameters` 建议至少写清：

- 参数类型
- 说明
- 是否必填
- 来源表和来源列
- 示例值
- SQL 片段
- 何时使用

目标不是写给人看得很学术，而是让 LLM 能更稳定地决定“何时加条件、怎么加条件”。

## 常见错误

### 1. 场景目录名与 `SCENARIO["name"]` 不一致

表现：

- 自动发现阶段直接报错

### 2. `skill_name` 写错

表现：

- 场景挂不到正确领域
- `load_scenario()` 查找失败

### 3. 资产路径写错

表现：

- 自动发现阶段就会报 `FileNotFoundError`

### 4. 该放 `shared/` 的资产仍然复制多份

表现：

- 多个场景中出现相同脚本或 SQL 副本
- 后期改一处容易漏改其余副本

## 一句话总结

新增场景时，优先把“一个场景 = 一个目录单元”维护完整；只要目录结构、`scenario.py` 和 `sql/main.sql` 合法，系统就会自动发现它，不再需要手改注册中心。
