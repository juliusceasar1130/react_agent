# 技能注册中心与加载机制说明

修改时间：2026-04-05 Asia/Shanghai

主要修改内容：
- 新增一份机制说明文档，解释技能系统的注册、渲染、加载和注入链路
- 统一说明 `DOMAIN_SKILLS`、`SCENARIOS_BY_SKILL`、`SKILLS` 的职责区别

## 背景

当前项目中的业务技能系统不是简单把一大段文本直接塞进系统提示词，而是采用分层装配机制：

1. 领域元数据与文档先组织成注册中心
2. 场景元数据与外部资产再挂接到对应领域
3. 中间件只暴露领域摘要
4. 详细领域/场景内容通过工具按需加载

这种结构的目标是：

- 降低 system prompt 的体积
- 支持渐进式披露
- 为固定场景和模板执行器预留空间

## 三层核心对象

### 1. `DOMAIN_SKILLS`

职责：

- 保存领域级运行时对象
- 汇总领域公共知识与场景摘要

典型字段：

- `name`
- `description`
- `domain_content`
- `scenario_summaries`
- `tags`

它更像“内部领域注册表”。

### 2. `SCENARIOS_BY_SKILL`

职责：

- 保存“领域 -> 场景列表”的映射
- 为场景查询和二级披露提供索引

它更像“内部场景注册表”。

### 3. `SKILLS`

职责：

- 提供给旧接口和中间件消费的兼容导出
- 保留 `name / description / content` 这种旧版结构

它不是原始数据源，而是由前两层加工得到的“兼容成品”。

## 模块职责分工

### `assets.py`

负责读取外部文本资产，例如：

- `domain.md`
- `.sql`

### `registry.py`

负责：

- 导入领域元数据
- 导入场景元数据
- 组装 `DOMAIN_SKILLS`
- 组装 `SCENARIOS_BY_SKILL`
- 最终生成 `SKILLS`

### `renderers.py`

负责把结构化数据渲染成给 LLM 使用的文本：

- `render_domain_for_llm()`
- `render_scenario_for_llm()`

### `loaders.py`

负责对外暴露：

- `load_domain_content()`
- `load_scenario_content()`

### `skill_tools.py`

负责在运行时通过工具把渲染后的文本写入消息上下文：

- `load_skill()`
- `load_scenario()`

### `skill_middleware.py`

负责在每次模型调用前把领域摘要注入系统提示词，提醒模型：

- 可用领域有哪些
- 固定场景要按需加载

## 运行时完整调用链

### 第 1 步：模块导入

当代码执行：

```python
from backend.app.skills import SKILLS
```

时，Python 会触发：

1. 加载 `backend.app.skills`
2. 执行 `skills/__init__.py`
3. 进一步导入 `registry.py`
4. 由 `registry.py` 顶层代码生成 `DOMAIN_SKILLS`、`SCENARIOS_BY_SKILL`、`SKILLS`

注意：

- 这是“模块导入时装配”
- 不是每次请求都重新扫描目录

### 第 2 步：中间件注入领域摘要

`SkillMiddleware` 只读取 `SKILLS` 中的：

- `name`
- `description`

然后把它们放进 system prompt。  
它不会直接把 `domain.md` 全文塞进系统提示词。

### 第 3 步：工具按需加载详细内容

当模型需要领域公共知识时：

- 调用 `load_skill("<domain_name>")`

该工具会：

1. 调用 `load_domain_content()`
2. 读取对应领域对象
3. 通过 `render_domain_for_llm()` 生成最终文本
4. 将文本写入 `ToolMessage`

当模型需要固定场景信息时：

- 调用 `load_scenario("<domain_name>", "<scenario_name>")`

该工具会：

1. 调用 `load_scenario_content()`
2. 渲染 workflow、rules、gotchas、模板引用
3. 写入 `ToolMessage`

## 为什么不是直接把所有内容都放进 system prompt

如果直接在系统提示词里放：

- 全部领域文档
- 全部场景说明
- 全部模板

会出现几个问题：

1. prompt 过大
2. 低频内容占上下文
3. 多领域之间容易互相污染
4. 固定场景扩展后难维护

所以当前方案选择：

- system prompt 只放领域摘要
- 详细内容通过工具按需加载

## 当前机制的边界

### 已支持

- 多领域显式注册
- 场景按领域挂载
- 领域与场景二级披露
- 外部 SQL 模板引用

### 尚未支持

- 自动扫描并发现所有领域
- 模板参数替换执行器
- 场景专用 report tool
- 场景级强校验参数 `required_scenario`

## 维护建议

1. 不要把 `SKILLS` 当作原始配置源
   - 它只是兼容导出层

2. 新领域应优先修改：
   - `domains/<domain>/`
   - `registry.py`

3. 新场景应优先修改：
   - `scenarios/*.py`
   - `sql/*.sql`
   - `registry.py`

4. 领域和场景都变动后，要验证：
   - `DOMAIN_SKILLS`
   - `SCENARIOS_BY_SKILL`
   - `SKILLS`
   - `load_skill()`
   - `load_scenario()`

## 一句话总结

技能注册中心机制的本质是：先把领域、场景和资产组织成内部注册表，再渲染成兼容层 `SKILLS` 和运行时加载文本，用“摘要暴露 + 按需加载”的方式控制模型上下文。
