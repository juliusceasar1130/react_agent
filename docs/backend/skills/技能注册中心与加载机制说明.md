# 技能注册中心与加载机制说明

修改时间：2026-04-06 21:22 Asia/Shanghai

主要修改内容：
- 更新为自动发现后的注册中心与加载链路说明
- 补充 `discovery.py`、`scope + path` 和场景失败即报错规则
- 同步新的目录结构与维护建议

## 背景

当前技能系统采用“摘要暴露 + 按需加载”的分层机制：

1. 领域元数据和场景元数据先被装配成注册表
2. `SkillMiddleware` 只把领域摘要注入 system prompt
3. 详细领域 / 场景内容通过 `load_skill()` / `load_scenario()` 工具按需进入上下文

本次重构后，注册中心不再手工 import 场景，而是由目录自动发现。

## 核心对象

### `DOMAIN_SKILLS`

职责：

- 保存领域级运行时对象
- 汇总领域公共知识与场景摘要

### `SCENARIOS_BY_SKILL`

职责：

- 保存 `领域 -> 场景列表` 映射
- 为 `get_scenario_by_name()` 和 `load_scenario_content()` 提供索引

### `SKILLS`

职责：

- 作为兼容旧接口的导出层
- 提供 `name / description / content` 结构给中间件使用

### `AssetRef`

本次重点字段：

- `scope`
  - `scenario`
  - `shared`
  - `domain`
- `path`
  作用域下的相对路径

## 模块职责

### `discovery.py`

负责：

- 自动发现领域
- 自动发现场景
- 校验目录名与元数据一致性
- 在注册阶段提前校验资产路径

### `assets.py`

负责：

- 解析 `scope + path`
- 确保资产路径不越界
- 读取文本文件和场景资产

### `registry.py`

负责：

- 调用 `discover_domains()`
- 调用 `discover_scenarios()`
- 组装 `DOMAIN_SKILLS`、`SCENARIOS_BY_SKILL`、`SKILLS`

### `renderers.py`

负责：

- 渲染领域全文
- 渲染场景全文
- 展示模板资产和脚本资产
- 展开第一份主 SQL 模板正文

### `loaders.py`

负责：

- `load_domain_content()`
- `load_scenario_content()`

### `skill_tools.py`

负责：

- `load_skill()`
- `load_scenario()`
- 更新运行时状态中的 `skills_loaded` / `scenarios_loaded`

## 自动发现规则

### 领域发现

系统扫描：

```text
backend/app/skills/domains/*/meta.py
```

并要求同目录下存在：

- `domain.md`

校验规则：

- 目录名必须等于 `DOMAIN_META["name"]`

### 场景发现

系统扫描：

```text
backend/app/skills/domains/<domain>/scenarios/*/scenario.py
```

校验规则：

- 场景目录名必须等于 `SCENARIO["name"]`
- `SCENARIO["skill_name"]` 必须等于所属领域名
- 资产路径必须能通过 `scope + path` 成功解析

## 运行时调用链

### 模块导入阶段

```text
backend.app.skills.__init__
  -> registry.py
    -> discover_domains()
    -> discover_scenarios()
    -> read_text_file(domain.md)
    -> 生成 DOMAIN_SKILLS / SCENARIOS_BY_SKILL / SKILLS
```

### 领域加载阶段

```text
load_skill(skill_name)
  -> get_skill_by_name()
  -> load_domain_content()
  -> render_domain_for_llm()
  -> ToolMessage(领域全文)
```

### 场景加载阶段

```text
load_scenario(skill_name, scenario_name)
  -> get_scenario_by_name()
  -> load_scenario_content()
  -> render_scenario_for_llm()
    -> _render_asset_refs()
    -> read_asset_text(first_sql_ref, scenario=...)
  -> ToolMessage(场景全文)
```

## 为什么这次维护成本更低

优化前：

- 新增场景要改 `scenarios/*.py`
- 还要改 `sql/*.sql`
- 还要改 `registry.py`

优化后：

- 新增场景只需要新建一个场景目录
- 目录内写好 `scenario.py` 和 `sql/main.sql`
- 系统自动发现，不再手改注册中心

这也是本次重构最主要的收益。

## 当前边界

当前仍然如此：

- 领域摘要只注入 system prompt
- 场景全文仍需 `load_scenario()` 按需加载
- SQL 工具仍按领域 `required_skill` 做权限校验
- 场景命中后，后续是否继续参考历史 SQL 示例仍是另一个待演进问题

## 维护建议

1. 不要把 `SKILLS` 当原始配置源
   - 它只是兼容导出结果

2. 新增领域优先改：
   - `domains/<domain>/meta.py`
   - `domains/<domain>/domain.md`

3. 新增场景优先改：
   - `domains/<domain>/scenarios/<scenario>/scenario.py`
   - `domains/<domain>/scenarios/<scenario>/sql/main.sql`

4. 只有真正跨场景复用的资产，才进入 `shared/`

## 一句话总结

当前技能注册中心已经从“手工挂接注册表”演进为“目录约定驱动的自动装配”；运行时接口保持不变，但维护者新增场景时的心智负担和遗漏风险显著降低。
