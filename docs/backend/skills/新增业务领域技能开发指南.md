# 新增业务领域技能开发指南

修改时间：2026-04-06 21:22 Asia/Shanghai

主要修改内容：
- 更新为“领域自动发现 + 场景目录聚合”新范式
- 补充领域根目录、场景目录和 `shared/` 公共资产区的组织约定
- 去掉旧版手工注册说明

## 背景

当前项目的业务技能系统已经采用自动发现机制：

1. 领域通过 `domains/<domain>/meta.py` 与 `domain.md` 被发现
2. 场景通过 `domains/<domain>/scenarios/<scenario_name>/scenario.py` 被发现
3. 运行时仍通过 `load_skill()` / `load_scenario()` 按需加载内容

这意味着新增领域时，重点从“手动改注册中心”变成了“把领域目录结构建正确”。

## 新增一个领域的标准结构

建议至少创建：

```text
backend/app/skills/domains/paint_shop_defect_analysis/
  __init__.py
  meta.py
  domain.md
  scenarios/
  shared/
    sql/
    scripts/
```

说明：

- `meta.py`
  领域元数据
- `domain.md`
  领域公共知识
- `scenarios/`
  当前领域下的固定场景
- `shared/`
  领域内多个场景复用的公共资产

## 第 1 步：编写 `meta.py`

参考模板：

```python
DOMAIN_META = {
    "name": "paint_shop_defect_analysis",
    "description": "涂装车间缺陷分析领域，用于处理缺陷分布、缺陷趋势、缺陷责任归因等统计与分析问题。",
    "tags": ["paint_shop", "defect_analysis", "scenario_enabled"],
}
```

要求：

- `name` 必须全局唯一
- `name` 必须与领域目录名一致
- `description` 用于领域摘要展示

## 第 2 步：编写 `domain.md`

`domain.md` 只放公共知识，不放所有场景的完整实现。

建议内容：

- 核心业务表
- 字段含义
- 主关联关系
- 通用业务规则
- 统计口径总原则
- 公共时间、状态和值域说明

不建议放：

- 各固定报表的完整 SQL
- 场景级 workflow
- 大段脚本实现

这些内容应该继续落在具体场景目录里。

## 第 3 步：按需新增场景

如果该领域已经有高频稳定问题，建议至少补一个样板场景：

```text
paint_shop_defect_analysis/
  scenarios/
    daily_defect_summary/
      scenario.py
      sql/
        main.sql
```

新增场景的细节请看：

- [新增场景技能开发指南](./新增场景技能开发指南.md)

## 第 4 步：验证自动发现

领域目录建好后，建议至少验证：

1. `get_skill_by_name("<domain_name>")` 能返回对象
2. `load_domain_content("<domain_name>")` 能输出领域正文
3. `list_scenarios_by_skill("<domain_name>")` 能列出该领域场景
4. `load_scenario("<domain_name>", "<scenario_name>")` 能成功加载场景

## 自动发现规则

当前实现会校验以下内容：

- 领域目录必须包含 `meta.py` 与 `domain.md`
- `DOMAIN_META["name"]` 必须等于领域目录名
- 场景目录必须包含 `scenario.py`
- 场景目录名必须等于 `SCENARIO["name"]`
- `SCENARIO["skill_name"]` 必须等于所属领域名
- 场景引用的资产路径必须可解析

只要这些约定成立，新领域和新场景就不需要额外修改 `registry.py`。

## 常见错误

### 1. 只创建目录，没有 `meta.py` 或 `domain.md`

表现：

- 领域不会被发现，或导入阶段直接报错

### 2. 领域目录名和 `DOMAIN_META["name"]` 不一致

表现：

- 自动发现阶段报错

### 3. 场景还沿用旧版 `scenarios/*.py` 和 `sql/*.sql`

表现：

- 系统不会自动发现该场景
- 新旧结构混用时容易增加维护成本

### 4. 共享资产没有进入 `shared/`

表现：

- 多个场景复制相同逻辑
- 修改公共规则时容易漏改

## 一句话总结

新增领域时，不再把重点放在“改注册中心”，而是把重点放在“领域目录规范 + 场景目录规范 + 公共资产边界”三件事上；目录结构正确，系统就会自动接入这个新领域。
