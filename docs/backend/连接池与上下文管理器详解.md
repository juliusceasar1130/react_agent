## 1. 上下文管理器

### 1.1 定义

**上下文管理器（Context Manager）** 是 Python 中用于管理资源的对象，定义了资源在进入和退出某个上下文时应该执行的操作。

### 1.2 核心作用

1. **资源管理**：自动获取和释放资源（文件、连接、锁等）
2. **异常安全**：即使发生异常，也能确保资源被正确释放

### 1.3 工作原理

```python
# with 语句语法
with expression as variable:
    # 代码块
```

**执行流程**：

```
1. 调用 expression.__enter__() 方法
   └─→ 返回值赋给 variable（可选）

2. 执行代码块

3. 无论代码块是否正常结束或抛异常
   └─→ 调用 expression.__exit__(exc_type, exc_val, exc_tb)
       └─→ 返回 False 表示传播异常
       └─→ 返回 True 表示抑制异常
```

### 1.4 实现方式

#### 方式1：使用类实现

```python
class DatabaseConnection:
    def __init__(self, db_url):
        self.db_url = db_url
        self.conn = None

    def __enter__(self):
        """进入上下文时调用"""
        print("连接数据库")
        self.conn = psycopg.connect(self.db_url)
        return self.conn

    def __exit__(self, exc_type, exc_val, exc_tb):
        """退出上下文时调用"""
        print("关闭数据库连接")
        if self.conn:
            self.conn.close()
        # 返回 False 表示不抑制异常
        return False

# 使用
with DatabaseConnection(DB_URL) as conn:
    cursor = conn.cursor()
    cursor.execute("SELECT * FROM users")
# 自动关闭连接，即使发生异常
```

#### 方式2：使用装饰器实现

```python
from contextlib import contextmanager

@contextmanager
def database_connection(db_url):
    """使用装饰器实现上下文管理器"""
    conn = None
    try:
        print("连接数据库")
        conn = psycopg.connect(db_url)
        yield conn  # yield 之前的代码是 __enter__ 逻辑
    finally:
        print("关闭数据库连接")
        if conn:
            conn.close()  # yield 之后的代码是 __exit__ 逻辑

# 使用
with database_connection(DB_URL) as conn:
    cursor = conn.cursor()
    cursor.execute("SELECT * FROM users")
# 自动关闭连接
```

### 1.5 典型应用场景

| 场景 | 示例 | 资源类型 |
|------|------|----------|
| 文件操作 | `with open('file.txt') as f:` | 文件句柄 |
| 数据库连接 | `with conn.cursor() as cursor:` | 数据库游标 |
| 线程锁 | `with lock:` | 线程锁 |
| 事务管理 | `with transaction:` | 数据库事务 |
| 临时目录 | `with tempfile.TemporaryDirectory() as tmpdir:` | 临时目录 |

### 1.6 上下文管理器的局限性

```python
class MyService:
    def __init__(self):
        # ❌ 问题：with 块在 __init__ 方法中立即结束
        with DatabaseConnection(DB_URL) as conn:
            self.conn = conn  # ← 在这里还可用
        # ← with 块结束，conn 被关闭
        # self.conn 现在指向已失效的连接！

    def query(self, sql):
        # ❌ 使用已关闭的连接会报错
        cursor = self.conn.cursor()
        cursor.execute(sql)
```

**核心问题**：
- `with` 语句在方法执行结束后立即退出
- 资源在 `__exit__` 中被释放
- 无法在类的整个生命周期内持有资源

## 2. 连接池

### 2.1 定义

**连接池（Connection Pool）** 是一种管理、复用数据库连接的机制，维护着一组可重用的连接，按需分配给应用程序。

### 2.2 为什么需要连接池？

#### 问题：每次创建连接的开销大

```python
# ❌ 无连接池：每次请求都创建新连接
def handle_request():
    conn = psycopg.connect(DB_URL)  # TCP 握手 + 认证 ≈ 50-100ms
    cursor = conn.cursor()
    cursor.execute("SELECT * FROM users")
    conn.close()  # 关闭连接

# 100 个请求 = 100 次连接创建 = 5-10 秒开销
```

#### 解决：复用已有连接

```python
# ✅ 有连接池：复用连接
pool = ConnectionPool(conninfo=DB_URL, min_size=5)

def handle_request():
    with pool.connection() as conn:  # ← 从池中获取连接 ≈ 1-5ms
        cursor = conn.cursor()
        cursor.execute("SELECT * FROM users")
    # ← 连接归还到池，供下次复用

# 100 个请求 ≈ 100 * 5ms = 0.5 秒（快 10-20 倍）
```

### 2.3 连接池的优势

| 优势 | 说明 | 性能提升 |
|------|------|----------|
| 减少连接创建开销 | 复用已有连接 | 10-20 倍 |
| 限制最大连接数 | 防止数据库连接耗尽 | 稳定性 ↑ |
| 支持并发请求 | 多个连接可同时使用 | 吞吐量 ↑ |
| 自动连接管理 | 自动获取、归还、重建 | 代码简洁 |

### 2.4 ConnectionPool 参数详解

```python
from psycopg_pool import ConnectionPool

pool = ConnectionPool(
    conninfo="postgresql://user:pass@host:port/db",  # 连接字符串
    min_size=1,     # 最小连接数
    max_size=10,    # 最大连接数
    timeout=30,     # 获取连接超时（秒）
    reopen=True,    # 自动重建关闭的连接
)
```

#### 参数说明

**conninfo**（必需）
- **类型**：字符串
- **格式**：`postgresql://用户名:密码@主机:端口/数据库名`
- **示例**：`postgresql://root:root@localhost:5432/rearch_agent`

**min_size**（推荐 1-5）
- **含义**：池中始终保持的最小连接数
- **影响**：
  - 太低（0）：首次请求需要创建连接，延迟增加
  - 太高：浪费资源，占用数据库连接
- **选择建议**：
  - 开发环境：1
  - 生产环境：2-5

**max_size**（推荐 10-50）
- **含义**：池中允许的最大连接数
- **影响**：
  - 太低：并发高时获取连接排队，性能下降
  - 太高：占用过多数据库连接，可能影响数据库
- **计算公式**：
  ```
  max_size = 并发请求数 × (平均请求时长 / 连接复用率)
  ```
- **选择建议**：
  - 低并发（<10）：5-10
  - 中并发（10-100）：20-50
  - 高并发（>100）：50-200

**timeout**（推荐 30-60 秒）
- **含义**：从池中获取连接的最大等待时间
- **行为**：
  - 30 秒内获取到连接：立即返回
  - 30 秒后仍无可用连接：抛出 `PoolTimeout`
- **调整建议**：
  - 正常场景：30 秒
  - 高并发场景：增加 max_size 而非 timeout

### 2.5 连接池工作原理

```
┌─────────────────────────────────────────────────────────┐
│                 ConnectionPool 实例                     │
│  ┌─────────────────────────────────────────────────┐   │
│  │  连接1 (active)   连接2 (idle)   ...  连接N     │   │
│  │  ↓               ↓               ↓               │   │
│  │  使用中          空闲可复用      空闲可复用      │   │
│  └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
                          │
                          │ 调用 pool.connection()
                          ▼
        ┌─────────────────────────────────────┐
        │  1. 检查是否有 idle 连接            │
        │  2. 有：返回 idle 连接              │
        │  3. 无：创建新连接（如果 < max_size）│
        │  4. 达到 max_size：等待（timeout）  │
        └─────────────────────────────────────┘
                          │
                          │ 使用完毕
                          ▼
        ┌─────────────────────────────────────┐
        │  连接归还到池中（变为 idle）        │
        │  下次请求可复用                     │
        └─────────────────────────────────────┘
```

### 2.6 连接池生命周期

```python
# 1. 初始化（应用启动时）
pool = ConnectionPool(conninfo=DB_URL, min_size=2, max_size=10)
# → 创建 2 个连接（min_size）
# → 可扩展到 10 个（max_size）

# 2. 获取连接
with pool.connection() as conn:
    # ← 从池中取出一个连接
    cursor = conn.cursor()
    cursor.execute("SELECT ...")
# ← with 块结束，连接归还到池

# 3. 自动扩容（并发请求）
# 假设有 5 个并发请求，池中只有 2 个连接：
# - 请求1：使用连接1
# - 请求2：使用连接2
# - 请求3：创建连接3
# - 请求4：创建连接4
# - 请求5：创建连接5
# - 请求6：等待（达到 min_size）

# 4. 关闭（应用关闭时）
pool.close()
# → 关闭所有连接
```

### 2.7 监控和调试

```python
# 获取连接池状态
stats = pool.stats

print(f"池大小: {stats.size}/{stats.max_size}")
# 输出：池大小: 5/10

print(f"总请求数: {stats.requests}")
# 输出：总请求数: 1523

print(f"返回错误数: {stats.errors}")
# 输出：返回错误数: 2

# 检查连接健康状态
for i in range(pool.max_size):
    with pool.connection() as conn:
        cursor = conn.cursor()
        cursor.execute("SELECT 1")
        print(f"连接 {i+1} 正常")
```

## 3. PostgresSaver 集成问题与解决

### 3.1 问题描述

在集成 LangChain 的 `PostgresSaver` 时遇到错误：

```python
# ❌ 错误代码
self.checkpointer = PostgresSaver.from_conn_string(settings.database_url)

# 错误信息
AttributeError: '_GeneratorContextManager' object has no attribute 'get_next_version'
```

### 3.2 根本原因

**`PostgresSaver.from_conn_string()` 返回的是上下文管理器，不是实例！**

```python
# PostgresSaver 的两种初始化方式

# 方式1：from_conn_string() - 返回上下文管理器
checkpointer_context = PostgresSaver.from_conn_string(DB_URI)
# 类型：<_GeneratorContextManager object>
# 必须用 with 语句使用

# 方式2：构造函数 - 返回实例
checkpointer = PostgresSaver(conn_pool)
# 类型：<PostgresSaver object>
# 可直接使用
```

### 3.3 为什么上下文管理器在类中不可行？

```python
class ResearchAgentService:
    def __init__(self):
        # ❌ 问题演示
        with PostgresSaver.from_conn_string(DB_URI) as checkpointer:
            self.checkpointer = checkpointer
            # ← 在这里还可用
        # ← with 块结束
        # checkpointer 的数据库连接已被关闭
        # self.checkpointer 现在指向一个失效的对象

    def process_message(self, message):
        # ❌ 使用已失效的 checkpointer
        result = self.agent.invoke(...)
        # 报错：连接已关闭
```

**时序分析**：

```
1. __init__() 开始
2. with 语句开始
3. 调用 __enter__() → 创建数据库连接
4. 将 checkpointer 赋值给 self.checkpointer
5. with 语句块结束 → 调用 __exit__()
6. 关闭数据库连接
7. __init__() 结束
8. 后续调用 process_message()
9. 使用 self.checkpointer → ❌ 连接已关闭
```

### 3.4 解决方案：使用 ConnectionPool

```python
# ✅ 正确实现
from psycopg_pool import ConnectionPool
from langgraph.checkpoint.postgres import PostgresSaver

class ResearchAgentService:
    def __init__(self):
        # 1. 创建连接池（不使用上下文管理器）
        self.conn_pool = ConnectionPool(
            conninfo=settings.database_url,
            min_size=1,
            max_size=10,
            timeout=30
        )

        # 2. 使用 PostgresSaver 构造函数
        #    不是 from_conn_string()，而是直接传参
        self.checkpointer = PostgresSaver(self.conn_pool)

        # 3. 首次使用时创建检查点表
        try:
            self.checkpointer.setup()
            logger.info("PostgresSaver 检查点表初始化成功")
        except Exception as e:
            logger.info(f"检查点表已存在: {e}")

        # 4. 创建 Agent（使用 checkpointer）
        self.agent = create_agent(
            model=llm,
            tools=tools,
            checkpointer=self.checkpointer
        )

    def process_message(self, message, session_id, config):
        # ✅ checkpointer 始终有效
        result = self.agent.invoke(
            {"messages": [HumanMessage(content=message)]},
            config=config
        )
        return result
```

### 3.5 方案对比

| 方式 | 代码 | 返回值 | 需要with | 适用场景 |
|------|------|--------|----------|----------|
| from_conn_string | `PostgresSaver.from_conn_string(DB_URI)` | ContextManager | ✅ 是 | 脚本、短期 |
| 构造函数 | `PostgresSaver(conn_pool)` | PostgresSaver | ❌ 否 | 类、长期 |

**为什么 ConnectionPool 可以直接传给 PostgresSaver？**

```python
# PostgresSaver 内部使用连接池的方式
class PostgresSaver:
    def __init__(self, conn_pool):
        self.conn_pool = conn_pool  # 保存连接池引用

    def get_tuple(self, config):
        """获取检查点"""
        with self.conn_pool.connection() as conn:  # ← 从池中获取连接
            cursor = conn.cursor()
            cursor.execute("SELECT * FROM checkpoints WHERE ...")
            return cursor.fetchall()
        # ← 连接自动归还到池
```

**关键点**：
- PostgresSaver 内部使用 `with self.conn_pool.connection()`
- 每次需要时从池中获取连接
- 操作完成后自动归还
- 连接池始终有效，不会关闭

## 4. 最佳实践

### 4.1 选择指南：何时用上下文管理器 vs 直接持有资源

| 场景 | 推荐方式 | 示例 |
|------|---------|------|
| **一次性脚本** | 上下文管理器 | 数据迁移脚本 |
| **单个请求处理** | 上下文管理器 | API 请求处理器 |
| **长期运行的服务** | 直接持有资源 | Agent 服务单例 |
| **需要跨请求共享** | 直接持有资源 | 连接池、缓存 |

### 4.2 上下文管理器最佳实践

```python
# ✅ 推荐：用于临时资源管理
def export_data():
    with PostgresSaver.from_conn_string(DB_URI) as checkpointer:
        checkpointer.setup()
        # 执行导出
        data = checkpointer.get_all_checkpoints()
        save_to_file(data)
    # 自动关闭连接

# ✅ 推荐：用于异常处理
def transaction_example():
    with connection.transaction():
        cursor.execute("UPDATE accounts SET balance = balance - 100")
        cursor.execute("UPDATE accounts SET balance = balance + 100")
    # 如果发生异常，自动回滚

# ❌ 避免：在类初始化中使用
class BadExample:
    def __init__(self):
        with PostgresSaver.from_conn_string(DB_URI) as checkpointer:
            self.checkpointer = checkpointer
        # ← 连接立即关闭
```

#### 资源清理

```python
class ResearchAgentService:
    def __init__(self):
        self.conn_pool = ConnectionPool(...)
        self.checkpointer = PostgresSaver(self.conn_pool)

    def __del__(self):
        """析构时清理资源"""
        if hasattr(self, 'conn_pool'):
            self.conn_pool.close()
            logger.info("连接池已关闭")

    # 或者使用显式关闭方法
    def shutdown(self):
        """显式关闭方法（推荐）"""

            self.conn_pool.close()
            logger.info("服务已关闭")

finally:
    service.shutdown()
```

### 4.4 错误处理

```python
class ResearchAgentService:
    def _initialize_agent(self):
        try:
            # 创建连接池
            self.conn_pool = ConnectionPool(
                conninfo=settings.database_url,
                min_size=1,
                max_size=10,
                timeout=30
            )

            # 创建 PostgresSaver
            self.checkpointer = PostgresSaver(self.conn_pool)

            # 创建检查点表
            self.checkpointer.setup()

        except PoolTimeout as e:
            logger.error(f"连接池超时: {e}")
            raise RuntimeError("无法连接到数据库，请检查连接配置")

        except Exception as e:
            logger.error(f"Agent 初始化失败: {e}", exc_info=True)
            # 清理已创建的资源
            if hasattr(self, 'conn_pool'):
                self.conn_pool.close()
            raise
```

## 5. 常见问题

### Q1: 什么时候使用上下文管理器？

**A**: 当资源使用是**临时的**、**局部的**时：

```python
# ✅ 适合：文件操作
with open('file.txt', 'r') as f:
    content = f.read()

# ✅ 适合：锁
with lock:
    critical_section()

# ✅ 适合：事务
with transaction():
    execute_sql()

# ❌ 不适合：需要长期持有资源
class Service:
    def __init__(self):
        with create_resource() as r:
            self.resource = r  # ← 立即失效
```

### Q2: 为什么 `from_conn_string()` 不能直接赋值？

**A**: 因为它返回的是**上下文管理器对象**，需要 `with` 语句进入：

```python
# from_conn_string 的简化实现
@contextmanager
def from_conn_string(conn_string):
    conn = psycopg.connect(conn_string)
    try:
        yield PostgresSaver(conn)  # ← yield 返回实例
    finally:
        conn.close()  # ← with 结束后关闭

# 返回的是生成器包装的上下文管理器
```

### Q3: ConnectionPool 会自动关闭吗？

**A**: 依赖 Python 垃圾回收，但建议显式关闭：

```python
# 方式1：依赖垃圾回收（不推荐）
pool = ConnectionPool(...)
# 程序结束时自动清理

# 方式2：显式关闭（推荐）
pool = ConnectionPool(...)
try:
    # 使用连接池
    pass
finally:
    pool.close()  # ← 显式关闭
```

### Q4: min_size 和 max_size 如何选择？

**A**: 根据并发量选择：

```
并发请求数 = QPS × 平均请求时长

例如：
- QPS = 10（每秒 10 个请求）
- 平均请求时长 = 0.5 秒
- 并发 = 10 × 0.5 = 5

建议：
- min_size = 2（保持热连接）
- max_size = 10（并发 × 2）
```

### Q5: 连接池耗尽怎么办？

**A**: 三种解决策略：

```python
# 策略1：增加 max_size
pool = ConnectionPool(..., max_size=20)  # 从 10 增加到 20

# 策略2：增加 timeout（治标不治本）
pool = ConnectionPool(..., timeout=60)  # 从 30 增加到 60

# 策略3：减少请求处理时间（治本）
# - 优化 SQL 查询
# - 减少不必要的操作
# - 使用缓存
```

### Q6: 如何调试连接池问题？

**A**: 使用日志和监控：

```python
import logging

# 启用 psycopg_pool 日志
logging.basicConfig(level=logging.DEBUG)
logger = logging.getLogger("psycopg_pool")

# 检查连接池状态
stats = pool.stats
print(f"连接数: {stats.size}/{stats.max_size}")
print(f"请求数: {stats.requests}")
print(f"错误数: {stats.errors}")

# 检查连接健康
with pool.connection() as conn:
    cursor = conn.cursor()
    cursor.execute("SELECT 1")
    print("连接正常")
```

## 6. 总结

### 6.1 核心概念对比

| 概念 | 作用 | 生命周期 | 适用场景 |
|------|------|----------|----------|
| **上下文管理器** | 自动管理资源获取和释放 | with 块内 | 临时资源使用 |
| **连接池** | 复用数据库连接，提升性能 | 应用生命周期 | 长期运行服务 |

### 6.2 PostgresSaver 集成关键点

1. **问题**：`from_conn_string()` 返回上下文管理器，不能直接赋值给类变量
2. **原因**：with 块结束后连接被关闭，后续使用会报错
3. **解决**：使用 `ConnectionPool` + `PostgresSaver` 构造函数
4. **优势**：连接在服务整个生命周期内有效

### 6.3 最佳实践清单

- [ ] 临时资源使用上下文管理器（`with` 语句）
- [ ] 长期资源直接持有（类实例变量）
- [ ] 连接池配置合理的 `min_size` 和 `max_size`
- [ ] 显式关闭连接池（`pool.close()`）
- [ ] 添加连接池状态监控和日志
- [ ] 处理连接池超时和错误

### 6.4 代码模板

```python
# ✅ 推荐模板：长期运行的服务
from psycopg_pool import ConnectionPool
from langgraph.checkpoint.postgres import PostgresSaver

class MyService:
    def __init__(self, db_url):
        # 创建连接池
        self.conn_pool = ConnectionPool(
            conninfo=db_url,
            min_size=2,
            max_size=20,
            timeout=30,
            reopen=True
        )

        # 创建 PostgresSaver
        self.checkpointer = PostgresSaver(self.conn_pool)

        # 初始化
        try:
            self.checkpointer.setup()
        except Exception:
            pass  # 表已存在

        logger.info("服务初始化成功")

    def shutdown(self):
        """显式关闭资源"""
        if hasattr(self, 'conn_pool'):
            self.conn_pool.close()
            logger.info("服务已关闭")

# 使用
service = MyService(DB_URL)
try:
    service.do_work()
finally:
    service.shutdown()
```
