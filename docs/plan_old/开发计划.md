# 业务知识 RAG 中间件开发计划

## 项目概述

**项目名称**: 业务知识 RAG 中间件  
**目标**: 实现动态业务知识检索和自动注入功能  
**预计工期**: 2-3 天  
**优先级**: 高

## 开发阶段

### 阶段 1: 基础实现（第 1 天）

#### 1.1 扩展 CustomState
- [ ] 在 `backend/app/agent/state.py` 中添加字段：
  - `rag_context: NotRequired[List[Document]]` - 存储检索到的文档
  - `rag_query: NotRequired[str]` - 存储触发检索的查询

**文件**: `backend/app/agent/state.py`  
**预计时间**: 15 分钟

#### 1.2 创建 BusinessRagMiddleware
- [ ] 创建文件 `backend/app/agent/middleware/rag_middleware.py`
- [ ] 实现基础类结构：
  ```python
  class BusinessRagMiddleware(AgentMiddleware[CustomState]):
      state_schema = CustomState
      
      def __init__(self, vector_store):
          self.vector_store = vector_store
          self._rag_system_message_id = "__business_rag_context__"
  ```
- [ ] 实现工具方法：
  - `_is_human_message()` - 判断是否为用户消息
  - `_format_knowledge_block()` - 格式化检索结果
  - `_has_rag_system_message()` - 检查是否已存在业务知识系统消息

**文件**: `backend/app/agent/middleware/rag_middleware.py`  
**预计时间**: 2 小时

#### 1.3 实现 before_model 钩子
- [ ] 实现核心检索逻辑：
  - 检测用户消息
  - 执行向量检索（`vector_store.similarity_search`）
  - 格式化检索结果
  - 创建 SystemMessage
  - 注入到 messages（替换或添加）
  - 更新 state

**文件**: `backend/app/agent/middleware/rag_middleware.py`  
**预计时间**: 2 小时

#### 1.4 创建向量存储工具函数
- [ ] 在 `backend/app/agent/utils/` 或新建 `backend/app/agent/utils/vector_store.py` 中创建：

- [ ] 配置向量库路径（`./chroma_langchain_db`）

**文件**: `backend/app/agent/utils/vector_store.py`（新建）

## 技术要点

### 关键技术点

1. **LangChain AgentMiddleware 使用**
   - 理解 `before_model` 钩子的执行时机
   - 理解如何修改 state 并返回更新

2. **向量检索**
   - Chroma 向量库的使用
   - DashScope Embedding 模型的配置
   - 相似度搜索参数调优

3. **消息处理**
   - SystemMessage 的创建和注入
   - Messages 列表的修改（替换/添加）
   - 消息去重逻辑

4. **状态管理**
   - CustomState 的扩展
   - State 更新的正确方式

### 注意事项

1. **性能考虑**
   - 向量检索可能增加延迟，考虑异步处理
   - 限制检索数量，避免 Token 消耗过大

2. **错误处理**
   - 向量检索失败时的降级处理
   - 空检索结果的处理

3. **兼容性**
   - 确保与现有中间件不冲突
   - 确保不影响现有功能

## 风险与应对

### 潜在风险

1. **向量库不存在或为空**
   - **应对**: 添加检查，如果向量库不存在则跳过 RAG 功能

2. **检索结果质量不佳**
   - **应对**: 设置相似度阈值，过滤低质量结果

3. **Token 消耗过大**
   - **应对**: 限制检索数量，优化知识格式化

4. **与现有中间件冲突**
   - **应对**: 仔细测试中间件执行顺序，确保兼容性

## 后续优化方向

1. **性能优化**
   - 实现检索结果缓存
   - 异步检索处理
   - 批量检索优化

2. **功能增强**
   - 支持多向量库检索
   - 支持混合检索（向量 + 关键词）
   - 支持检索结果重排序

3. **可观测性**
   - 添加检索指标监控
   - 添加检索质量评估
   - 添加使用情况统计
