# pgvector 向量检索优化开发方案

## 1. 项目概述

### 1.1 背景
当前系统使用 Chroma 作为向量存储，存在以下限制：
- 无法充分利用 PostgreSQL 的 ACID 特性和事务支持
- 难以实现复杂的元数据过滤和联合查询
- 不支持与业务数据库的深度集成
- 检索性能在大数据量下可能受限

### 1.2 目标
基于 pgvector 扩展实现向量检索优化，支持：
- **三种元数据类型**：DDL（表结构）、Documentation（业务术语）、SQL Example（标准范例）
- **元数据过滤检索**：根据元数据类型进行精准过滤和检索
- **高性能检索**：利用 pgvector 的索引优化和 PostgreSQL 的查询能力
- **无缝迁移**：从 Chroma 平滑迁移到 pgvector，保持 API 兼容性

### 1.3 核心价值
- **统一数据管理**：向量数据与业务数据在同一数据库，便于管理和备份
- **精准检索**：基于元数据类型的过滤，提高检索准确率
- **扩展性强**：支持复杂的 SQL 查询和业务逻辑集成
- **生产就绪**：利用 PostgreSQL 的成熟生态和运维工具

## 2. 技术方案

### 2.1 数据库架构设计

#### 2.1.1 表结构设计（由 LangChain 自动创建）

**重要说明**：
- ✅ 表结构由 LangChain `PGVector` 类**自动创建**，无需手动创建
- ✅ 表名是固定的：`langchain_pg_collection` 和 `langchain_pg_embedding`
- ✅ 首次初始化 `PGVector` 时会自动创建表结构
- ✅ 不需要手动指定向量维度，LangChain 会根据 Embedding 模型**自动设置**
- ✅ 同一个 Collection 中的所有文档必须使用相同维度的向量（由同一个 Embedding 模型生成）

**自动创建的表结构**：

```sql
-- Collection 元数据表（langchain_pg_collection）
CREATE TABLE langchain_pg_collection (
    uuid UUID PRIMARY KEY,              -- Collection 的唯一标识符
    name VARCHAR UNIQUE NOT NULL,        -- Collection 名称（对应 PGVector 的 collection_name 参数）
    cmetadata JSONB                     -- Collection 级别的元数据（可选）
);

-- 文档和向量存储表（langchain_pg_embedding）
CREATE TABLE langchain_pg_embedding (
    uuid UUID PRIMARY KEY,              -- 文档记录的唯一标识符
    collection_id UUID NOT NULL,        -- 关联到 langchain_pg_collection.uuid
    embedding VECTOR,                   -- 向量嵌入（维度由 embedding 模型决定，自动设置）
    document TEXT,                      -- 文档的原始文本内容
    cmetadata JSONB,                    -- 文档级别的元数据（完全可自定义）
    custom_id VARCHAR                   -- 自定义 ID（可选）
);
```

**自动创建的索引**：
- 主键索引：`langchain_pg_collection.uuid`、`langchain_pg_embedding.uuid`
- 唯一索引：`langchain_pg_collection.name`
- 外键索引：`langchain_pg_embedding.collection_id`
- 向量索引：`langchain_pg_embedding.embedding`（HNSW 或 IVFFlat，自动创建）

**可选：手动创建元数据索引（提升查询性能）**

如果需要优化元数据过滤查询性能，可以手动创建以下索引：

```sql
-- 元数据索引（提升查询性能）
CREATE INDEX IF NOT EXISTS idx_embedding_metadata_type 
ON langchain_pg_embedding USING GIN ((cmetadata->>'type'));

CREATE INDEX IF NOT EXISTS idx_embedding_metadata_table_name 
ON langchain_pg_embedding USING BTREE ((cmetadata->>'table_name')) 
WHERE cmetadata->>'type' = 'ddl';

CREATE INDEX IF NOT EXISTS idx_embedding_metadata_domain 
ON langchain_pg_embedding USING BTREE ((cmetadata->>'domain'));

CREATE INDEX IF NOT EXISTS idx_embedding_metadata_complexity 
ON langchain_pg_embedding USING BTREE ((cmetadata->>'complexity')) 
WHERE cmetadata->>'type' = 'sql_example';
```

**注意**：这些索引是可选的，LangChain 会自动创建向量索引用于相似度搜索。

#### 2.1.2 元数据 Schema 定义

**DDL 类型**：
```json
{
  "type": "ddl",
  "table_name": "orders",
  "domain": "sales",
  "schema": "public",
  "description": "订单表，记录所有电商交易流水"
}
```

**Documentation 类型**：
```json
{
  "type": "documentation",
  "domain": "finance",
  "term": "毛利",
  "aliases": ["Gross Profit", "收益", "利润"]
}
```

**SQL Example 类型**：
```json
{
  "type": "sql_example",
  "sql": "SELECT ...",  // 可选：如果 document 中已包含完整 SQL，可省略以避免冗余
  "complexity": "high",
  "domain": "sales",
  "description": "计算每个大区的季度毛利环比增长率"
}
```

**设计说明**：
- `document` 字段（对应 `langchain_pg_embedding.document`）：**必须**包含"问题描述 + SQL 代码"的完整文本，用于向量检索（Embedding）
- `cmetadata` 字段（对应 `langchain_pg_embedding.cmetadata`）：**完全可自定义**的 JSONB 类型，存储文档元数据
- `cmetadata.sql` 字段：**可选**，存储纯 SQL 代码
  - **优点**：便于程序化提取、格式化展示、元数据查询
  - **缺点**：如果 `document` 中已包含完整 SQL，会造成数据冗余
  - **建议**：如果系统需要从元数据中快速提取 SQL（不依赖文本解析），则保留；否则可以省略

**重要提示**：
- ✅ `cmetadata` 是 **JSONB 类型**，可以存储任意 JSON 数据
- ✅ 在创建 `Document` 时，通过 `metadata` 参数传入自定义内容
- ✅ 支持任意键值对，没有固定格式限制
- ✅ 支持嵌套对象、数组等复杂数据结构
- ✅ 可以使用 `filter` 参数根据 `cmetadata` 中的字段进行过滤搜索

### 2.2 核心组件设计

#### 2.2.1 PgVectorStoreWrapper 类（基于 LangChain PGVector）

```python
from langchain_postgres import PGVector
from langchain_core.embeddings import Embeddings
from langchain_core.documents import Document
from typing import List, Dict, Optional, Any

class PgVectorStoreWrapper:
    """
    基于 LangChain PGVector 的轻量包装
    
    使用 LangChain 官方 PGVector 类，提供业务特定的便利方法：
    - 自动创建表结构（langchain_pg_collection 和 langchain_pg_embedding）
    - 自动处理向量维度（根据 Embedding 模型）
    - 支持元数据过滤检索
    """
    
    def __init__(
        self,
        connection_string: str,
        embedding_function: Embeddings,
        collection_name: str = "business_knowledge"
    ):
        """
        Args:
            connection_string: PostgreSQL 连接字符串
                - 支持 postgresql:// 格式（会自动转换为 postgresql+psycopg://）
                - 推荐使用 postgresql+psycopg:// 格式
            embedding_function: Embedding 模型实例
                - LangChain 会根据模型维度自动设置 VECTOR 类型
                - 例如：baai/bge-m3 自动使用 1024 维向量
            collection_name: Collection 名称
                - 对应 langchain_pg_collection.name 字段
                - 用于逻辑分组，不同 Collection 共享同一个表
        """
        # 转换连接字符串格式（如果需要）
        if connection_string.startswith("postgresql://"):
            connection_string = connection_string.replace(
                "postgresql://", "postgresql+psycopg://", 1
            )
        
        # 使用 LangChain PGVector（自动创建表结构）
        self._vector_store = PGVector(
            embeddings=embedding_function,
            collection_name=collection_name,
            connection=connection_string,
        )
        self.collection_name = collection_name
    
    def similarity_search(
        self,
        query: str,
        k: int = 5,
        filter: Optional[Dict[str, Any]] = None,
        **kwargs
    ) -> List[Document]:
        """
        相似度搜索
        
        Args:
            query: 查询文本
            k: 返回文档数量
            filter: 元数据过滤条件，例如：
                {"type": "ddl", "domain": "sales"}
                支持复杂查询，如：{"page": {"$gte": 1}}
        """
        return self._vector_store.similarity_search(
            query=query, k=k, filter=filter, **kwargs
        )
    
    def similarity_search_with_score(
        self,
        query: str,
        k: int = 5,
        filter: Optional[Dict[str, Any]] = None,
        **kwargs
    ) -> List[Tuple[Document, float]]:
        """
        带分数的相似度搜索
        
        Returns:
            List of (Document, score) tuples
        """
        return self._vector_store.similarity_search_with_score(
            query=query, k=k, filter=filter, **kwargs
        )
    
    def similarity_search_by_type(
        self,
        query: str,
        doc_type: str,
        k: int = 5,
        domain: Optional[str] = None,
        **kwargs
    ) -> List[Document]:
        """
        按类型检索（便捷方法）
        
        Args:
            query: 查询文本
            doc_type: 文档类型 ("ddl", "documentation", "sql_example")
            k: 返回文档数量
            domain: 业务域过滤（可选）
        """
        filter_dict: Dict[str, Any] = {"type": doc_type}
        if domain:
            filter_dict["domain"] = domain
        return self.similarity_search(query, k=k, filter=filter_dict, **kwargs)
    
    def add_documents(
        self,
        documents: List[Document],
        ids: Optional[List[str]] = None,
        **kwargs
    ) -> List[str]:
        """批量添加文档"""
        return self._vector_store.add_documents(
            documents=documents, ids=ids, **kwargs
        )
    
    def delete(self, ids: Optional[List[str]] = None, **kwargs) -> bool:
        """删除文档"""
        return self._vector_store.delete(ids=ids, **kwargs)
    
    @property
    def vector_store(self):
        """访问底层 PGVector 实例"""
        return self._vector_store
```

### 2.3 迁移方案

#### 2.3.1 数据迁移脚本

```python
# vector_migration.py
from langchain_community.vectorstores import Chroma
from langchain_core.documents import Document
from typing import List, Dict, Any
import logging

logger = logging.getLogger(__name__)

def migrate_from_chroma_to_pgvector(
    chroma_path: str,
    pgvector_store: PgVectorStoreWrapper,
    batch_size: int = 100,
    collection_name: Optional[str] = None
):
    """
    从 Chroma 迁移数据到 pgvector
    
    步骤：
    1. 读取 Chroma 数据库中的所有文档
    2. 批量转换并插入到 pgvector（使用 LangChain PGVector 的 add_documents）
    3. 验证数据完整性
    4. 生成迁移报告
    
    Args:
        chroma_path: Chroma 数据库路径
        pgvector_store: PgVectorStoreWrapper 实例
        batch_size: 批量插入大小
        collection_name: 目标 Collection 名称（如果与 pgvector_store 不同）
    """
    # 1. 读取 Chroma 数据
    chroma_store = Chroma(
        persist_directory=chroma_path,
        embedding_function=pgvector_store.vector_store.embeddings
    )
    
    # 获取所有文档（Chroma 没有直接的方法，需要遍历）
    # 注意：Chroma 的 API 可能不同，需要根据实际情况调整
    all_docs = []
    all_ids = []
    
    # 2. 批量插入到 pgvector
    total_migrated = 0
    for i in range(0, len(all_docs), batch_size):
        batch_docs = all_docs[i:i + batch_size]
        batch_ids = all_ids[i:i + batch_size] if all_ids else None
        
        try:
            pgvector_store.add_documents(
                documents=batch_docs,
                ids=batch_ids
            )
            total_migrated += len(batch_docs)
            logger.info(f"Migrated {total_migrated}/{len(all_docs)} documents")
        except Exception as e:
            logger.error(f"Failed to migrate batch {i//batch_size}: {e}")
            raise
    
    # 3. 验证数据完整性
    # 可以通过查询 pgvector 验证文档数量
    # 注意：LangChain PGVector 没有直接的方法获取文档总数，可能需要 SQL 查询
    
    # 4. 生成迁移报告
    report = {
        "source": chroma_path,
        "target": pgvector_store.collection_name,
        "total_documents": len(all_docs),
        "migrated": total_migrated,
        "status": "success" if total_migrated == len(all_docs) else "partial"
    }
    
    logger.info(f"Migration completed: {report}")
    return report
```

- `psycopg` 是 PostgreSQL 的 Python 驱动，`langchain-postgres` 会自动安装

### 5.2 数据库要求
- PostgreSQL >= 14
- pgvector 扩展已安装
- 数据库用户有 CREATE TABLE、CREATE INDEX 权限

## 9. 附录

### 9.1 SQL 示例

**创建扩展（在 PostgreSQL 数据库中执行）**：
```sql
-- 在 PostgreSQL 数据库中执行（不是 Python 代码）
CREATE EXTENSION IF NOT EXISTS vector;
```

**LangChain 自动创建的表结构查询**：
```sql
-- 查看 Collection 列表
SELECT uuid, name, cmetadata 
FROM langchain_pg_collection;

-- 查看某个 Collection 的文档数量
SELECT COUNT(*) 
FROM langchain_pg_embedding 
WHERE collection_id = (
    SELECT uuid FROM langchain_pg_collection WHERE name = 'business_knowledge'
);

-- 查看文档和向量（带相似度计算）
SELECT 
    e.uuid,
    e.document,
    e.cmetadata,
    1 - (e.embedding <=> $1::vector) as similarity
FROM langchain_pg_embedding e
JOIN langchain_pg_collection c ON e.collection_id = c.uuid
WHERE c.name = 'business_knowledge'
  AND e.cmetadata->>'type' = 'ddl'
  AND e.cmetadata->>'domain' = 'sales'
ORDER BY e.embedding <=> $1::vector
LIMIT 10;
```

**手动创建元数据索引（可选，提升查询性能）**：
```sql
-- 为 type 字段创建 GIN 索引（支持 JSONB 查询）
CREATE INDEX IF NOT EXISTS idx_embedding_metadata_type 
ON langchain_pg_embedding USING GIN ((cmetadata->>'type'));

-- 为 domain 字段创建 BTREE 索引
CREATE INDEX IF NOT EXISTS idx_embedding_metadata_domain 
ON langchain_pg_embedding USING BTREE ((cmetadata->>'domain'));

-- 为 table_name 字段创建部分索引（仅 DDL 类型）
CREATE INDEX IF NOT EXISTS idx_embedding_metadata_table_name 
ON langchain_pg_embedding USING BTREE ((cmetadata->>'table_name')) 
WHERE cmetadata->>'type' = 'ddl';
```

**注意**：
- LangChain PGVector 会自动创建表结构和向量索引
- 上述 SQL 示例仅用于手动查询和性能优化
- 实际使用中，通过 Python API 操作，无需手动编写 SQL
